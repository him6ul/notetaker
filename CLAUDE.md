This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

NoteTaker is a native macOS menu-bar app (SwiftUI, macOS 14+) that listens to a live
conversation — your mic **and** the other side of a call via system audio — transcribes
it locally with WhisperKit, extracts a summary + ideas + action items with a local Ollama
model, and emails the package via Gmail SMTP. Everything runs on-device; the only thing
that leaves the Mac is the final email, and nothing is sent until the user approves it in
a review window.

## Build & run

The Xcode project is **generated by XcodeGen** from `project.yml` — `NoteTaker.xcodeproj`
is not the source of truth and may be gitignored. After any change to `project.yml`
(dependencies, entitlements, Info.plist keys, build settings), regenerate before building:

```bash
xcodegen generate               # regenerate NoteTaker.xcodeproj from project.yml
open NoteTaker.xcodeproj         # then Run in Xcode
```

Command-line build:

```bash
xcodebuild -project NoteTaker.xcodeproj -scheme NoteTaker \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath build build
open build/Build/Products/Debug/NoteTaker.app
```

There is **no test target** — no `xcodebuild test`, no unit/UI tests exist. Verify changes
by building and running the app (menu-bar waveform icon → Start Listening → Stop & Review).

Running the app end-to-end requires external services the app talks to at runtime:
`ollama serve` with the configured model pulled (`llama3.1:8b` default), and a Gmail App
Password entered in Settings. First launch prompts for **Microphone** and **Screen
Recording** permissions (ScreenCaptureKit needs the latter for system audio).

## Architecture

The pipeline is a linear flow driven by one orchestrator:

```
mic (AVAudioEngine) ─┐  per-source        every ~8s      on Stop        user approves
system (SCKit) ──────┴─► SourceBuffer ─► Transcriber ─► TranscriptStore ─► Summarizer ─► ReviewModel/View ─► Mailer
                        (NSLock)         (WhisperKit)   (merged, labeled) (Ollama)      (edit / Send / Discard) (curl SMTP)
```

**`AppState` (`AppState.swift`) is the mediator for the entire pipeline** — a `@MainActor
ObservableObject` that owns one instance of every subsystem (`micCapture`, `systemCapture`,
`store`, `transcriber`) and coordinates them so the subsystems never reference each other.
It is by far the most connected type in the codebase; treat it as the place where control
flow lives, and prefer adding coordination logic to the subsystem it belongs in rather than
growing `AppState` further. State is a `Phase` enum (`idle → preparing → listening →
processing → reviewing → error`); the menu bar and status text derive from it.

Key design points that span multiple files:

- **Two audio sources are transcribed separately, then merged** — this is *how* speaker
  labeling works. Mic samples are tagged `Speaker.me`, system audio `Speaker.others`;
  `TranscriptStore` merges both into one time-ordered transcript with "Me:"/"Others:"
  prefixes. Do not merge the audio streams before transcription — that loses the labels.
- **Chunked, timer-driven transcription.** A `flushTimer` fires every `chunkSeconds` (8s)
  and on Stop; each fire drains both `SourceBuffer`s and transcribes them. `SourceBuffer`
  is `NSLock`-guarded because audio callbacks append off the main thread. Chunks under
  ~0.5s of audio (`samples.count < 8000` at 16 kHz) are skipped as silence.
- **`Transcriber` is an `actor`** specifically so the mic and system chunks never run the
  Whisper model concurrently — calls serialize naturally. WhisperKit consumes 16 kHz mono
  Float samples, so `Resampler` converts each source's native format first.
- **The Ollama contract is structured output.** `Summarizer` POSTs to
  `localhost:11434/api/chat` with a JSON `format` schema; `MeetingNotes` (Codable) must
  stay in sync with that schema — changing one without the other breaks decoding.
- **Nothing is emailed automatically.** `finishAndReview()` opens an editable review window
  (`ReviewModel`/`ReviewView`); `Mailer` only runs when the user clicks Send. On send
  failure the window stays open for retry. `Mailer` shells out to `curl` for
  `smtps://smtp.gmail.com:465` using the Keychain-stored App Password.
- **Menu-bar activation dance.** The app is an accessory (`LSUIElement`) with no dock icon.
  To front the review window it flips `NSApp.setActivationPolicy(.regular)`, then back to
  `.accessory` when the window closes. `WindowCloseDelegate` bridges the window's red-X
  close (a discard) vs. programmatic close.

Config & secrets: `AppSettings` (UserDefaults) holds non-secret prefs; the Gmail App
Password lives only in `Keychain`. Entitlements (in `project.yml`) run **sandbox off** with
`device.audio-input` + `network.client`.
